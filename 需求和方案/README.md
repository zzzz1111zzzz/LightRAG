## 当前结论

当前项目已经具备 workspace 级存储隔离基础和部署级认证能力，但尚不构成完整的多租户、多用户、细粒度权限系统。后续实现必须建立“身份—成员关系—权限—workspace 上下文—RAG 存储”的完整链路。

## 实施原则

- 客户端提交的 workspace 标识只是访问目标提示，不是授权凭证。
- 权限必须由服务端基于持久化 membership 计算，不能只信任 JWT 中的 role claim。
- 不能通过修改一个全局 `LightRAG.workspace` 来服务并发请求。
- 控制面元数据与 RAG 数据面分离设计。
- 先完成底层契约和控制面，再用上传—查询—删除垂直链路验证，最后扩展到所有路由和 WebUI。
- 每个阶段独立分支、独立测试、独立 PR，避免在 `main` 上直接开发。
